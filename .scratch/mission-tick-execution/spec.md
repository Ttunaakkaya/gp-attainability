## Purpose

Continue the existing mission execution refactor. A diagnostic caller can inspect
and advance one mission without changing scientific results or taking ownership of
sampling, planning, or record ordering. The ordinary runner uses the same path.
This supports later controlled research; copying, recovery and charged planning
delay are outside this increment.

## Interface and testing seam

Keep the execution owner module-private in `sim/mapping.py`. Its documented
internal interface is construction, `read()`, `advance()` and `finish()`; tests
exercise these operations and returned evidence, never its mutable fields.
The existing public `run_mapping(config, method)` remains the consumer seam.

- Construction completes startup at physical tick zero, including existing
  method-specific preview, receipt, assimilation, planning and initial records.
- `read()` returns an immutable diagnostic view: status, last reached tick/time,
  tuple-valued positions/headings, active-plan identity, and attempted, received
  and assimilated observation counts. No prediction or planning happens on reads.
- `advance()` performs at most one next physical transition and closes all existing
  work due at the reached tick. A sampling tick includes receipt, assimilation,
  outgoing planning and its frame. Interior P decisions follow recorded motion.
- `finish()` advances to a terminal outcome and returns the existing artifact
  schema. `run_mapping` delegates to this same execution path.
- A terminal outcome is finalized once. Further advances leave it unchanged;
  artifact reads are independent copies and cannot mutate owned evidence.

## Preservation requirements

Preserve the incoming sample/motion plan and forecast identities separately from
outgoing plan identities. Use the last physically reached tick, not the sampling
interval's origin, in diagnostic views. Never invent an off-clock final sample or
an outgoing plan at the deadline.

Preserve nominal preview failures before real receipt for sweep/greedy, and the
post-receipt failures of adaptive/DP/P. Rejected controls leave the last accepted
physical state; GP update failure retains receipts and assimilation flags without
replaying rejected data. Only existing handled ControlFailure cases become failed
outcomes; unrelated errors still propagate.

The final runtime is frozen at terminal processing. Pauses by a caller while the
mission is running count in elapsed wall runtime, but never advance simulated
time. Existing operation timing fields retain their scopes. Pausing is not a
planning-delay experiment.

## Validation

Test sequential and partial advancement through the documented interface against
literal clock/count/provenance expectations, then compare returned mission evidence
with the preserved 14-case reference set. Do not replace the frozen reference with
outputs generated by changed code. Include fractional clocks, a deadline before the
next measurement, an interior P replacement, startup and mid-mission failures,
view isolation and terminal idempotence. Retain independent numerical and existing
consumer tests. CI fixes may intentionally improve SOGP numerical behavior; report
any affected preservation case explicitly rather than loosening normalization.

Implement one red/green behavior slice at a time. Run targeted tests and type checks
during implementation, then full coverage/static/diagnostic checks and independent
standards/spec review. Commit the bounded increment and verify GitHub CI.
