## Verified code behavior

**Vehicle state and commands.** `IdealAgent` maintains position and yaw, with a display-only height. It advances planar position using `dt * v * [cos(yaw), sin(yaw)]` and yaw using `dt * omega`; yaw rate is clipped to `[-v/r_min, v/r_min]`. It subscribes to `geometry_msgs/Twist` on relative topic `cmd_vel`, using `linear.x` and `angular.z`, and publishes clock-stamped `PoseStamped` on `pose`. This node is a kinematic Dubins-style model: no mass, acceleration, thrust, rudder, current or wave state appears. Commands persist until another arrives; no command-timeout stop is implemented here. [ideal_agent.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/robot_model/robot_model/ideal_agent.py)

**Planning versus low-level control.** The waypoint generator constructs a repeating lawnmower route from `field_range`, interpolates it using Dubins paths, and advances waypoints from `curr_pose`. It publishes the current segment as `PoseArray` on `target_line`, containing two endpoint positions. It does not expose an external full-route input in this file. [waypoints_generator.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/controller/controller/waypoints_generator.py)

`LOS` consumes that segment and `curr_pose`, then publishes a `Float32` desired heading on `target_angle`. The heading controller consumes desired heading and pose, applying proportional heading feedback and publishing `cmd_vel` with configured fixed forward speed. These are distinct candidate intervention levels: segment, heading and velocity; none is an acceleration/thrust interface. [los.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/controller/controller/los.py), [angle_fbcontroller.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/controller/controller/angle_fbcontroller.py)

**The environmental quantity is currently coverage importance.** `PhiUpdate` initializes a grid and importance array, then periodically updates it using current robot positions and per-agent Boolean sensing-region masks. Its implemented rule adds `dt * (delta_increase - delta_decrease * sensing_performance * phi)` within each region and clips values to `[0.01, 1]`. It publishes `/phi` and `/sum_phi`. Inputs are `curr_pose_array` and each agent's `sensing_region`; they are not measured scalar-field values. No GP update, noisy observation, sample timestamp, sample-delivery event or discrete sensing budget appears in this node. After readiness, the timer reuses the latest received poses/masks without a freshness check. Consequently `/phi` cannot simply be interpreted as GP posterior variance. [phi_update.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/field_manager/field_manager/phi_update.py)

**Orchestration.** The main launch creates per-agent launches plus central pose collection, importance updates and visualization. It accepts 1–4 agents and optionally records all topics. Configuration files can override node defaults. [main.launch.py](https://github.com/htnk-lab/Multi-USV-Benchmark/blob/79e77cecf28a2ccfeebe5ce8eb3cd0c60c3c5b35/benchmark_main/launch/main.launch.py)

## Implications and unresolved scope

- **Inference:** travel delays caused by turning and path following transfer naturally to this kinematic setting. Reduced speed could be an explicitly injected disturbance, but is not recovery authority under the agreed fixed limits. Water-current forces or actuator failures would require additional modeling; this inspection does not establish them as native benchmark features.
- **Inference:** changing route segments while retaining the existing motion stack is a plausible way to extend the benchmark. Full-route replacement, assignment handling and publisher ownership still need design and validation.
- **Inference:** GP mapping needs explicit sample acquisition/delivery and estimator integration. Dropping pose messages alone would not reproduce a sensing dropout: the importance updater continues with stored state. Observation delay, missed samples and physical immobility therefore require distinct experimental definitions.
- **Unknown:** per-agent launch/remappings, pose conversion, sensing-performance details, imported dependencies, effective parameter values, simulated-time behavior, collision enforcement and runtime cost were outside these six files. No general collision-safety guarantee or complete absence of GP code is claimed. Before integration, verify these and declare how sample time differs from receipt time.

This check supports a staged experiment, not a final architecture: preserve the Python study's uncertainty target and sampling semantics when adding ROS execution, and report the benchmark's coverage metric separately.
